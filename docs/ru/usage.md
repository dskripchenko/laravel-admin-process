# Использование

## Список экземпляров

Колонки: ID (открывает страницу экземпляра), процесс, версия, статус,
текущее состояние, бизнес-ключ, есть ли открытые инциденты, создан и
изменён. Текущее состояние — это активные листовые состояния или финальное
состояние завершённого экземпляра.

Фильтры: процесс, статус, бизнес-ключ, «С инцидентами», дата создания в
интервале. Список обновляется сам каждые `refresh.list` секунд.

Действия в строке — **Приостановить**, **Возобновить**, **Отменить** —
требуют `admin.process.operate` и причину. Отмена может сначала
компенсировать выполненные шаги.

## Список инцидентов

Сначала открытые инциденты, затем самые новые. Колонка экземпляра открывает
страницу экземпляра, где и устраняется причина: инцидент лишь фиксирует,
что требуется участие человека. **Закрыть инцидент** (с
`admin.process.operate`) закрывает его с решением и причиной.

## Страница экземпляра

`/admin/screens/process-instance?id=<uuid>`.

Сводка вверху: статус, текущее состояние и его подпись, бизнес-ключ,
объект, родитель, отметки времени и последний шаг, который сдвинул
экземпляр.

Вкладки:

| Вкладка | Содержимое |
|---|---|
| **Схема** | граф процесса с позицией экземпляра: пройденные состояния, текущие, пройденные переходы, проблемы (эффект с неизвестным исходом, открытый инцидент). Опрашивается каждые `refresh.flow` секунд. Составные состояния и дочерние процессы раскрываются на месте. |
| **Ожидает** | события, которые экземпляр принимает сейчас (с целевым состоянием и признаком, решает ли условие), и его таймеры. |
| **Контекст** | данные процесса в виде JSON. |
| **Эффекты** | все эффекты, новые первыми: статус, семантика, попытка, следующая попытка, ошибка. |
| **Инциденты** | инциденты и события, которые ждут обработки или были отклонены. |
| **Журнал** | последние записи, новые первыми: что произошло, кто, почему. |

## Действия оператора

Панель команд страницы. Каждое действие требует причину, которая попадает
в журнал вместе с администратором.

| Действие | Право | Вызов движка |
|---|---|---|
| Приостановить / Возобновить | operate | `suspend` / `resume` — события ждут, эффекты не запускаются |
| Отменить | operate | `cancel`, при необходимости сначала с компенсацией |
| Повторить эффект | operate | `retryEffect` для упавшего, отменённого или неизвестного эффекта |
| … с «Исход неизвестен: беру ответственность за повторный вызов» | **manage** | `retryEffect(confirmUnsafe: true)` — эффект at-most-once с неизвестным исходом |
| Закрыть инцидент | operate | `resolveIncident` |
| Доставить повторно | operate | `redeliver` для отклонённого события |
| Перевести в состояние | manage | `transitionTo`, с действиями выхода и входа или без них |
| Изменить контекст | manage | `patchContext` — JSON-объект `{"key": value}` задаёт ключи верхнего уровня; массив JSON Patch (RFC 6902) делает всё остальное |
| Задать исход эффекта | manage | `resolveEffect` — выполнен с результатом или не выполнен с кодом |
| Пропустить эффект | manage | `skipEffect` — продолжить так, будто эффект выполнен |

На схеме в панели выбранного состояния есть **Перевести в это состояние**
(manage), с подтверждением.

Движок применяет ручную операцию по порядку вместе с другими событиями
экземпляра. С синхронной очередью она уже выполнена к моменту ответа
панели, поэтому отказ (эффект не упал, экземпляр завершён) показывается
как ошибка. С настоящей очередью панель сообщает, что операция принята, а
результат появляется в журнале.

## Безопасность

Методы страницы привязаны к действиям с правами, поэтому панель отказывает
в операторском методе пользователю без соответствующего права, даже если
метод вызван напрямую через API. Тесты пакета проверяют, что каждый
операторский метод страницы недоступен пользователю с правом только на
просмотр.

## Настройка

Карточка дашборда — обычный виджет: ограничьте, кто её видит, через
`ProcessOverviewWidget::make()->permission(...)`, когда размещаете её на
своём дашборде. Интервалы обновления и длина журнала задаются в конфиге.
